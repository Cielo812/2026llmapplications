## 一、定义与概念边界

用一段话给出准确、通俗的定义。标明英文名称、缩写以及讨论范围。关键主张后附对应来源链接。

## 二、背景与工作原理

说明概念为何出现、要解决什么问题。分步骤解释输入、处理过程与输出；需要时加入流程图或公式，解释每个符号。不要用术语堆叠替代解释。

## 三、应用案例

| 要素 | 内容 |
|:---|:---|
| 使用者与问题 | 谁在什么情况下遇到什么困难 |
| 材料与权限 | 材料来源、版本、是否公开或已授权 |
| 输入与输出 | 输入什么、最终交付什么 |
| 模型与工具 | 使用的平台、模型及可获得的版本信息 |
| 流程与分工 | 人、模型和外部工具各做什么 |
| 核验标准 | 怎样判定成功、由谁核验 |
| 失败与接管 | 哪些情况下停止或交给人处理 |

如果案例为模拟，请在此明确标注“教学模拟”；如果没有运行，请标注“待验证设计”或“文献分析”。

## 五、相近概念与常见误区

至少比较一个相近概念，用具体例子解释一种常见误解。说明两者可以怎样结合。

## 六、局限与负责任使用

说明模型能力、资料覆盖、版本变化和工具权限等限制。交代个人信息处理、引用核对、提示注入防范与人工接管中与本案例有关的部分。
